# معیار پذیرش پنل سازنده

## هسته و ورود
- [ ] سازنده اصلی فقط پس از اعتبارسنجی نشست امضاشده توسط سرور وارد شود.
- [ ] نقش سازنده از جدول کاربران در سمت سرور خوانده شود؛ نقش ذخیره‌شده در مرورگر مرجع نباشد.
- [ ] کمک‌سازنده از رکورد فعال `builder_access` و هویت معتبر کاربر سرور شناسایی شود.
- [ ] کاربر عادی، صراف، کارمند یا مشتری نتواند با تغییر localStorage یا URL وارد پنل شود.
- [ ] در صورت نبودن RPC، خطای شبکه یا منقضی‌شدن نشست، دسترسی رد شود (fail closed).

## ماژول‌ها
- [ ] هر ۲۶ ماژول با کلید ثابت و مسیر مستقل در منو وجود داشته باشد.
- [ ] جست‌وجوی سریع ماژول‌ها با صفحه‌کلید و موبایل کار کند.
- [ ] وضعیت هر ماژول از backend بیاید یا صادقانه «پیکربندی‌نشده» نمایش داده شود.
- [ ] همه عملیات تغییردهنده از API مجاز سمت سرور عبور کند.
- [ ] خطا و نتیجه واقعی backend در UI نمایش داده شود؛ پاسخ ساختگی ممنوع است.

## RBAC و ممیزی
- [ ] سازنده اصلی به همه ماژول‌ها دسترسی دارد.
- [ ] کمک‌سازنده فقط تب‌های تخصیص‌یافته را می‌بیند و عملیات خارج از مجوز را در سرور نیز نمی‌تواند اجرا کند.
- [ ] مجوزهای view/create/edit/approve/manage جداگانه اعمال شوند.
- [ ] هر تغییر مدیریتی همراه عامل، زمان، ماژول، هدف و نتیجه ثبت شود.
- [ ] تعلیق کمک‌سازنده دسترسی نشست جاری را در درخواست بعدی نیز ببندد.

## اطلاعات و پشتیبان
- [ ] شمارش‌ها و اندازه دیتابیس از منبع سروری معتبر بیاید.
- [ ] localStorage فقط به عنوان حافظه مرورگر معرفی شود.
- [ ] بکاپ واقعی شامل DB rows، Auth configuration/data، Storage objects و فایل‌های لازم باشد.
- [ ] قبل از اعلام موفقیت بکاپ، integrity check و آزمون restore در محیط مستقل انجام شود.
- [ ] restore دارای پیش‌نمایش، کنترل دامنه، تأیید دو مرحله‌ای و ثبت ممیزی باشد.

## کیفیت
- [ ] GitHub Actions build موفق باشد.
- [ ] تست واحد مجوزها و تست منفی (unauthorized) موفق باشد.
- [ ] تست مرورگر در عرض موبایل، تبلت و دسکتاپ انجام شود.
- [ ] خطاهای console و network بررسی شوند.
- [ ] هیچ کلید service_role، رمز، token یا داده واقعی A1 در bundle یا repository قرار نگیرد.

## وضعیت فعلی
این فهرست معیار هدف است؛ موارد تیک‌نخورده هنوز تأیید نشده‌اند. شاخه بازسازی منتشر نشده است.
